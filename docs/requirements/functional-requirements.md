# Функциональные требования Grafio

Статус: целевой контур продукта. Документ описывает наблюдаемое поведение. Формулы, состав показателей и правила данных не повторяются здесь: они являются источниками для проверки требований.

## 1. Контекст и финансовый отчёт

| ID | Система должна | Проверка |
|---|---|---|
| FR-01 | Позволять выбрать доступные организацию, юридическое лицо, кабинет и завершённую неделю. | Выбор меняет все связанные представления и показывает точные даты периода. |
| FR-02 | Показывать по источникам статус получения, полноту, время обновления и доступность зависимых показателей. | Неполный источник не превращается в нулевой результат. |
| FR-03 | Показывать версию расчёта, состав включённых опций и состояние сверки. | Контекст отчёта доступен без открытия технических журналов. |
| FR-04 | Рассчитывать и показывать выручку, возвраты, выкупы, статьи расходов, себестоимость, маржу и маржинальность по утверждённым паспортам. | Контрольный набор совпадает с [паспортами показателей](../data/metric-passports.md). |
| FR-05 | Рассчитывать контроль структуры и считать сверку пройденной только при точном `Δ = 0`. | Ненулевое расхождение выводит отчёт в состояние «Требует проверки». |
| FR-06 | Показывать недельную структуру в ₽ и % с корректной семантикой метрики и без скрытой нормализации. | Режим % описывает маржинальность и доли структуры; режим ₽ — абсолютные суммы. |
| FR-07 | Открывать детализацию статьи до доступных товаров, операций и группы «Без привязки к товару». | Сумма детализации объясняет доступную часть статьи. |
| FR-08 | Показывать историю и различия версий методики. | У недели с другой версией есть отметка и объяснение изменения. |

## 2. Качество данных и методика

| ID | Система должна | Проверка |
|---|---|---|
| FR-09 | Отдельно хранить и показывать состояния источника, полноты, сверки, методики и показателя. | Несколько ограничений видны одновременно и не сводятся к общей «ошибке». |
| FR-10 | Оставлять неизвестную операцию нераспределённой и доступной для исследования. | Автоматическая категория не назначается без опубликованного правила. |
| FR-11 | Позволять клиенту создать кейс по неизвестной операции, расхождению, неполноте или дубликату. | Кейс наследует период, кабинет, сумму и затронутые показатели. |
| FR-12 | Позволять клиенту добавлять доказательства, комментарии и задачи, затем отправлять запрос в Grafio. | История статусов сохраняется: новая → нужны данные → отправлено → опубликовано → закрыто. |
| FR-13 | Предоставлять Admin Console для исследования запроса, проекта правила и контрольной сверки. | Клиентский sidebar и canvas не отображаются во внутреннем контуре. |
| FR-14 | Требовать область, период действия и способ применения перед публикацией правила. | Нельзя опубликовать кабинетное исключение без обоснования. |
| FR-15 | Поддерживать пересчёт истории и применение правила вперёд с даты. | Пересчёт создаёт новые версии отчётов; исходные остаются доступными. |
| FR-16 | Передавать клиентскому кейсу версию методики, результат сверки, период и объяснение публикации. | Клиент видит результат, но не может редактировать правило. |

## 3. Планы, аналитика и личный дашборд

| ID | Система должна | Проверка |
|---|---|---|
| FR-17 | Создавать версионный недельный или месячный план для выбранной области и набора показателей. | План хранит единицу, цель, правило сравнения, период и состав кабинетов. |
| FR-18 | Сопоставлять план с фактом той же области, единицы и методики. | Несовместимые единицы или базы ДРР не сравниваются. |
| FR-19 | Показывать тематические графики недельной аналитики, значения точек и блок «Что изменилось». | Тип визуализации соответствует данным: линия, область, столбцы или накопление. |
| FR-20 | Открывать «Мой дашборд» с пустого состояния и набором только поддержанных KPI и графиков. | Старт не содержит предустановленных виджетов. |
| FR-21 | Позволять добавлять, выбирать, перемещать, менять размер, настраивать и удалять личные виджеты в режиме редактирования. | Вне режима редактирования нет лишних контролов виджета. |
| FR-22 | Поддерживать листы дашборда: создание, переключение, переименование, быстрые действия и отображение числа объектов. | Новый лист показывает состояние «С чего начать?». |
| FR-23 | Показывать миникарту, масштаб, линейки и сетку только в canvas-контуре. | Панели не перекрывают toolbar, sidebar и панель листов; сетка отсутствует в остальных разделах. |

## 4. Команда и безопасность

| ID | Система должна | Проверка |
|---|---|---|
| FR-24 | Показывать состав команды и назначать роли в пределах организации. | Недоступные роли и области нельзя выдать через интерфейс или прямую ссылку. |
| FR-25 | Управлять персональными настройками безопасности, активными сессиями, ключами и двухфакторной защитой. | Критические действия имеют подтверждённый результат и отражаются в истории. |
| FR-26 | Разделять клиентские роли и роль администратора Grafio. | Администратор Grafio не назначается в команде клиента; клиент не получает доступ к Admin Console. |
| FR-27 | Сохранять аудит существенных действий: изменение доступа, публикация методики, пересчёт, активация плана и закрытие кейса. | Запись содержит автора, время, область, действие и результат. |

## Источники проверки

Детальные требования первой версии FR-01—FR-27 и информационные требования IR-01—IR-15 остаются в [Сводный реестр требований первой версии Grafio](first-release-requirements-register.md); проверка покрытия — в [Матрица прослеживаемости Grafio](traceability-matrix.md). Настоящий документ объединяет их с последующим функциональным контуром планов, личного дашборда, команды и Admin Console.
