# Бизнес-правила Grafio

Статус: целевой контур продукта. Правила фиксируют обязательную логику предметной области. Они не являются функциональными или нефункциональными требованиями: одна функция может реализовывать несколько правил, а одно правило проверяться в нескольких сценариях.

## Правила финансового контура

| ID | Правило | Проверка |
|---|---|---|
| RULE-01 | Неделя отчёта начинается в понедельник и заканчивается в воскресенье; незавершённая неделя не выдаётся за финальный результат. | В контексте отчёта показан полный диапазон ПН–ВС. |
| RULE-02 | Отсутствие, ноль и невозможность расчёта — разные состояния. | Каждое состояние имеет отличимое значение, текст и причину. |
| RULE-03 | Сверка проходит только при точном `Δ = 0` до форматирования. | Любое ненулевое значение создаёт состояние «Требует проверки». |
| RULE-04 | Общие суммы и входящие в них статьи не суммируются повторно. | Контрольный расчёт не содержит двойного учёта. |
| RULE-05 | Промежуточные значения не округляются до суммирования; форматирование пользователя не меняет расчёт и сверку. | Контрольный пример с копейками даёт один результат при разных настройках представления. |
| RULE-06 | Операция без товарной связи остаётся в сумме статьи и показывается отдельной группой. | Отсутствие связи не исключает операцию из итога. |
| RULE-07 | Неизвестная операция не получает автоматическую категорию без опубликованного правила. | Запись сохраняется нераспределённой и создаёт сигнал качества. |

## Правила методики и истории

| ID | Правило | Проверка |
|---|---|---|
| RULE-08 | Версия правила имеет автора, причину, область и период действия. | Публикация блокируется при отсутствии обязательного реквизита. |
| RULE-09 | Правило по умолчанию действует на подтверждённую общую область; кабинетное исключение требует обоснования. | В опубликованной версии видно исключение и его причину. |
| RULE-10 | Пересчёт создаёт новую версию отчёта, а не меняет опубликованную историю. | Исходная версия доступна для сравнения. |
| RULE-11 | Применение методики вперёд не изменяет прошлые отчёты и требует даты начала действия и причины. | История сохраняет прежнюю методику, а граница изменения видна пользователю. |
| RULE-12 | Клиент может предложить категорию операции, но не публикует системную методику. | Предложение хранится в кейсе до решения администратора Grafio. |
| RULE-13 | Публикация правила невозможна при неопределённой области, неоднозначной операции, двойном учёте или ненулевой обязательной сверке без задокументированной причины. | Проверки блокируют публикацию и называют невыполненное условие. |

## Правила планов, дашборда и доступа

| ID | Правило | Проверка |
|---|---|---|
| RULE-14 | План и факт не смешиваются; план сравнивается только с совместимыми областью, единицей и методикой факта. | Несовместимое сопоставление не выводится как отклонение. |
| RULE-15 | Состав кабинетов фиксируется в версии плана; подключение нового кабинета не меняет активный план автоматически. | Для изменения состава создаётся новая версия или явное действие пользователя. |
| RULE-16 | Личный dashboard не задаёт корпоративную методику и не меняет факт. | Настройка виджета влияет только на представление пользователя. |
| RULE-17 | Клиентская роль действует только в назначенной организации и области; роль администратора Grafio находится в отдельном внутреннем контуре. | Клиент не получает Admin Console, а администратор Grafio не назначается через клиентскую команду. |
