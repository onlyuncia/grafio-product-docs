# Требования к интерфейсам Grafio

Требования к интерфейсам описывают обмен между пользователем, Grafio, его компонентами и внешними источниками. Они не зависят от выбора фреймворка или транспорта сообщений.

## 1. Пользовательские интерфейсы

| ID | Интерфейс | Обязательное поведение |
|---|---|---|
| INT-01 | Клиентское рабочее пространство | Toolbar передаёт текущий контекст организации, кабинета и периода; разделы отчёта, аналитики, планов, контроля и команды не скрывают качество данных. |
| INT-02 | Недельный отчёт и аналитика | Графики показывают единицу, тип метрики, значения точек и объяснение изменения; сравниваемые серии имеют общую временную основу. |
| INT-03 | Контроль расчётов | Кейс показывает тип проблемы, сумму, период, статусы, доказательства, ответственного и доступное следующее действие. |
| INT-04 | Планы | Форма не даёт создать несовместимое сравнение и показывает версию, дату действия, область и статус активации. |
| INT-05 | Мой дашборд | Новый dashboard пуст; сетка, миникарта, масштаб, линейки и панели canvas существуют только в этом разделе. В режиме просмотра редакторские контролы скрыты. |
| INT-06 | Admin Console | Это отдельный полноэкранный интерфейс без клиентского sidebar и canvas. Он содержит очередь, редактор правила, контроль, публикацию и возврат в рабочее пространство. |
| INT-07 | Команда и безопасность | Назначение роли, 2FA, сессии и ключи — самостоятельные понятные действия с видимым результатом; опасные действия требуют подтверждения. |
| INT-08 | РНП | Таблица сохраняет контекст кабинета и периода, различает дни, недельные суммы и итог; выбор состава метрик доступен без изменения данных. |
| INT-09 | Товары | Каталог показывает активные фильтры, сортировку и итог выборки; карточка отделяет текущую себестоимость от истории. |
| INT-10 | Студия | Поиск и просмотр поддержанных KPI и графиков позволяют добавить копию на выбранный лист; состояние карточки библиотеки и её копии на листе различаются. |

### Admin Console (INT-06)

Admin Console — полноэкранное рабочее пространство администратора Grafio без клиентского sidebar и canvas. Верхняя полоса содержит поиск, профиль и возврат в клиентское пространство. Левая колонка — очередь проблем, а не навигация по продукту. [Демонстрационный экран](../../screenshots/09-admin-console.png) показывает расположение областей.

| Область | Обязательное содержание и действие |
|---|---|
| Очередь | Тип сигнала, кабинет и период, влияние, статус и ответственный; поиск, фильтрация, принятие в работу и связь с существующей проблемой. |
| Карточка и доказательства | Исходный сигнал, историю решений, контрольные суммы, операции, исходные поля, загрузки и действующее правило. Рабочая гипотеза отделена от подтверждённой причины. |
| Проект правила | Условие, денежный компонент, знак, категорию, приоритет, область и период действия. |
| Контроль | Показатели до и после правила, нераспределённые и неоднозначные операции, точную сверку и влияние на незатронутые показатели. |
| Публикация | Способ применения, затронутые отчёты, предварительный просмотр уведомления и итог повторной сверки; блокирующая причина видна рядом с недоступным действием. |

Интерфейс показывает отдельно область обнаружения сигнала, область действия правила, область пересчёта и получателей уведомления. Исключение для одного кабинета требует обоснования; непроверенный период не обозначается как пересчитанный. Клиент получает результат и ссылку на версию, но не доступ к редактору системного правила. Блокирующие условия публикации заданы в [жизненном цикле методики](../processes/calculation-lifecycle.md), действия и аудит — в [критериях приёмки](acceptance-criteria.md) и [NFR](non-functional-requirements.md).

## 2. Внешний API Wildberries

| ID | Контракт | Требование |
|---|---|---|
| API-01 | Поиск финансового отчёта | Для недельного периода используются утверждённые методы и параметры из [Контракта WB](../data/wb-data-contract.md). |
| API-02 | Детализация | Пагинация начинается с `rrdId = 0`, продолжается последним курсором и завершается terminal-ответом `204`. |
| API-03 | Безопасность | Токен WB хранится только по защищённой ссылке `secret_ref`; он не передаётся в логи, raw-ответы, БД аналитики и сообщения об ошибке. |
| API-04 | Повторы | Повтор загрузки не создаёт дубли операций, страниц или версий отчёта. |
| API-05 | Изменение схемы | Незнакомое поле или значение сохраняется в raw-документе и создаёт наблюдение качества; оно не получает выдуманную интерпретацию. |

## 3. Внутренние прикладные интерфейсы

| ID | Команда или чтение | Вход | Результат |
|---|---|---|---|
| APP-01 | `RequestSourceLoad` | кабинет, источник, период, причина, `command_id` | `job_id` или ссылка на активное идемпотентное задание |
| APP-02 | `GetReportVersion` | область, период, версия отчёта | показатели, состояния качества, методика и ссылки на детализацию |
| APP-03 | `OpenCalculationCase` | проблема, контекст, сумма, доказательства | новый клиентский кейс и его статус |
| APP-04 | `SubmitCaseToGrafio` | кейс, комментарий, вложения | внутренний запрос с историей передачи |
| APP-05 | `PublishRuleVersion` | проект правила, область, период, применение, результат контроля | версия методики, задания пересчёта или дата применения вперёд |
| APP-06 | `CreatePlanVersion` | область, период, показатели, единицы, цели | черновик версии плана |
| APP-07 | `ActivatePlanVersion` | версия плана, полномочия пользователя | активный план и запись аудита |

Команда не должна ожидать длительную фоновую работу: она возвращает `job_id` не позднее 2 секунд на стартовом профиле. Все контракты версионируются.

## 4. События и ошибки

| ID | Категория | Требование |
|---|---|---|
| EVT-01 | События загрузки | Фиксируются создание задания, сохранение источника, завершение/ошибка загрузки, проверка качества и публикация отчёта. |
| EVT-02 | События методики | Фиксируются создание запроса, переход статуса, готовность к публикации, публикация правила, пересчёт и передача результата клиенту. |
| EVT-03 | Аудит | Существенное событие содержит автора, время, область, действие, результат, `correlation_id` и неизменяемую ссылку на объект. |
| ERR-01 | Ошибка | Возвращает безопасный код, этап, время и `correlation_id`; не содержит токенов, персональных секретов или полного raw-ответа. |
| ERR-02 | Недоступность источника | Не мешает читать уже опубликованную версию; новое зависимое значение получает объяснимое состояние. |

## 5. Требования представления

1. Основные пользовательские пути доступны с клавиатуры; фокус видим, поля имеют подписи, а состояние не передаётся только цветом.
2. Состояние загрузки, неполноты, сверки и методики формулируется понятным языком с указанием следующего действия.
3. Интерфейс поддерживает две последние стабильные версии Chrome и Edge.

Детали асинхронного конвейера: [интеграционная спецификация](../architecture/integration-specification.md). Пользовательские экраны и их состояния показаны в [прототипе](../../prototype/README.md), а операционные переходы — в [процессах](../processes/operational-workflows.md).
