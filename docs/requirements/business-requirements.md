# Бизнес-требования Grafio

Бизнес-требования определяют ожидаемый результат Grafio для клиента и команды сервиса. Поведение системы раскрыто в [функциональных требованиях](functional-requirements.md), потребности ролей — в [пользовательских требованиях](user-requirements.md).

## Цель продукта

Grafio помогает команде продавца маркетплейса принимать финансовые решения на основании воспроизводимого недельного результата: видеть состав выкупов, расходов и маржи, понимать качество исходных данных и прослеживать изменение до операции и версии методики.

## Бизнес-требования

| ID | Требование | Критерий достижения |
|---|---|---|
| PBR-01 | Финансовая команда получает недельный результат по доступному кабинету и юридическому лицу без ручного сведения выгрузок. | За выбранную завершённую неделю доступны выручка, выкупы, расходы, себестоимость, маржа, суммы и доли статей; состав налога, рекламы и пользовательских расходов указан явно. |
| PBR-02 | Результат пригоден для управленческого решения только при видимых качестве данных и ограничениях методики. | Неполнота, неизвестная операция, расхождение, версия расчёта и недоступный показатель не скрываются и не заменяются нулём. |
| PBR-03 | Пользователь может объяснить изменение статьи до доступных товаров и исходных операций. | Из суммы открывается детализация с сохранением периода, кабинета и версии отчёта. |
| PBR-04 | Компания сохраняет сравнимую историю, даже когда изменяется методика расчёта или источник данных. | Недели можно сравнить с отметкой о различии методик; опубликованный отчёт неизменяем, пересчёт создаёт новую версию с автором, причиной, областью и периодом действия. |
| PBR-05 | Организация может вести несколько оплаченных кабинетов одного маркетплейса в рамках одного юридического лица. | Кабинеты изолированы в доступе и контексте; каждый дополнительный кабинет учитывается как отдельное платное подключение, без ограничения «одно юрлицо — один кабинет». |
| PBR-06 | Пользователь управляет операционными планами, не смешивая план с фактом. | План хранится как версия с областью, периодом, единицей и целью; факт рассчитывается независимо от плана. |
| PBR-07 | Команда получает единое рабочее пространство для отчётов, РНП, товаров, аналитики, планов, Студии, контроля расчётов и собственных KPI. | Разделы используют доступный контекст организации, кабинета и периода; «Мой дашборд» остаётся личным свободным полотном. |
| PBR-08 | Системная методика расчёта управляется Grafio, а не клиентом. | Клиент создаёт кейс и передаёт доказательства; только внутренняя Admin Console публикует версию правила и способ применения. Общее правило действует в подтверждённой области, кабинетное исключение требует обоснования. |
| PBR-09 | Руководитель организации контролирует доступ команды и состояние безопасности. | Доступ назначается по ролям и области; доступны управление участниками, сессиями, ключами и двухфакторной защитой. |
| PBR-10 | Внутренняя команда Grafio может безопасно разбирать системные проблемы и выпускать методику без воздействия на несвязанные данные. | Правило имеет область действия, проверку сверки, историю публикаций и отдельный аудит действий администратора. |
