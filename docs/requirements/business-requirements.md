# Бизнес-требования Grafio

Статус: целевой контур продукта. Документ разделяет ожидаемый результат для бизнеса и способы его реализации. Детализация функций находится в [Функциональные требования Grafio](functional-requirements.md), потребности ролей — в [Пользовательские требования Grafio](user-requirements.md).

## Цель продукта

Grafio помогает команде продавца маркетплейса принимать финансовые решения на основании воспроизводимого недельного результата: видеть состав выкупов, расходов и маржи, понимать качество исходных данных и прослеживать изменение до операции и версии методики.

## Бизнес-требования

| ID | Требование | Критерий достижения |
|---|---|---|
| BR-01 | Финансовая команда получает недельный результат по доступному кабинету и юридическому лицу без ручного сведения выгрузок. | За выбранную завершённую неделю доступны выручка, выкупы, расходы, себестоимость, маржа и их объяснимая структура. |
| BR-02 | Результат пригоден для управленческого решения только при видимых качестве данных и ограничениях методики. | Неполнота, неизвестная операция, расхождение, версия расчёта и недоступный показатель не скрываются и не заменяются нулём. |
| BR-03 | Пользователь может объяснить изменение статьи до доступных товаров и исходных операций. | Из суммы открывается детализация с сохранением периода, кабинета и версии отчёта. |
| BR-04 | Компания сохраняет сравнимую историю, даже когда изменяется методика расчёта или источник данных. | Опубликованный отчёт неизменяем; пересчёт создаёт новую версию с автором, причиной, областью и периодом действия. |
| BR-05 | Организация может вести несколько оплаченных кабинетов одного маркетплейса в рамках одного юридического лица. | Кабинеты изолированы в доступе и контексте; новая связь не создаёт ограничение «одно юрлицо — один кабинет». |
| BR-06 | Пользователь управляет операционными планами, не смешивая план с фактом. | План хранится как версия с областью, периодом, единицей и целью; факт рассчитывается независимо от плана. |
| BR-07 | Команда получает единое рабочее пространство для отчётов, аналитики, планов, контроля расчётов и собственных KPI. | Разделы используют единый контекст организации, кабинета и периода; «Мой дашборд» остаётся личным свободным полотном. |
| BR-08 | Системная методика расчёта управляется Grafio, а не клиентом. | Клиент создаёт кейс и передаёт доказательства; только внутренняя Admin Console публикует версию правила и способ применения. |
| BR-09 | Руководитель организации контролирует доступ команды и состояние безопасности. | Доступ назначается по ролям и области; доступны управление участниками, сессиями, ключами и двухфакторной защитой. |
| BR-10 | Внутренняя команда Grafio может безопасно разбирать системные проблемы и выпускать методику без воздействия на несвязанные данные. | Правило имеет область действия, проверку сверки, историю публикаций и отдельный аудит действий администратора. |

## Границы результата

Первая версия не обещает автоматического определения причины отклонения, управления рекламными кампаниями, изменения данных Wildberries или самостоятельной публикации клиентом системных правил. Grafio показывает факты, ограничения и доказательства; вывод о причине подтверждает пользователь или администратор в пределах своей роли.
