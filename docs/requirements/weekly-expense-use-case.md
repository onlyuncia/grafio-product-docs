# Пользовательский сценарий недельного анализа расходов

Сценарий показывает, как пользователь исследует расходы недельного отчёта Grafio: от выбора недели до проверки суммы по операциям.

## Карточка сценария

| Поле | Значение |
|---|---|
| Идентификатор | UC-01 |
| Название | Проанализировать структуру расходов за отчётную неделю |
| Основной пользователь | Менеджер маркетплейса или аналитик |
| Заинтересованный участник | Владелец бизнеса / клиент, который просматривает результат |
| Поддерживающий участник | Администратор Grafio, отвечающий за правила расчёта |
| Событие запуска | Пользователю нужно проверить маржу завершённой недели и объяснить изменение расходов |
| Результат | Пользователь понимает состав расходов, их отношение к выкупам, изменение относительно прошлых недель и качество исходных данных |

## Термины сценария

- **Отчётная неделя** — период с понедельника по воскресенье.
- **Срез по начислению** — операции относятся к неделе, в которой отражены в финансовом отчёте. Это рабочий бизнес-термин; точное поле источника будет определено в контракте данных.
- **Выкупы, ₽** — выручка, отражённая за неделю, минус возвраты, отражённые за эту неделю. Возврат заказа прошлой недели уменьшает выкупы текущей.
- **Доля статьи в выкупах** — сумма статьи / выкупы × 100% при положительных и полных данных.
- **Исторический ряд** — значения выбранных показателей за доступные прошлые недели с той же логикой расчёта либо с явно указанным различием версий.

## Предусловия

1. Пользователь вошёл в Grafio и имеет доступ к кабинету продавца.
2. Кабинет связан с юридическим лицом.
3. Для отчёта существует опубликованная версия правил расчёта.
4. Grafio может запросить финансовые данные WB либо показать состояние их отсутствия.
5. Настройки налога, себестоимость, рекламные и пользовательские расходы могут быть подключены опционально; их отсутствие обрабатывается явно.

## Основной поток

| Шаг | Действие и реакция системы | Что получает пользователь |
|---|---|---|
| 1 | Пользователь выбирает кабинет, юридическое лицо и завершённую неделю | Понятный контекст отчёта: кабинет, юридическое лицо, даты ПН–ВС |
| 2 | Grafio показывает состояние источников, время последнего обновления, версию расчёта и включённые опции | Понимание актуальности и состава будущего результата |
| 3 | Grafio получает доступные финансовые операции WB и подключённые дополнительные данные | Основание для расчёта с раздельным статусом каждого источника |
| 4 | Grafio проверяет полноту, отсутствие дублей, известность типов операций и расхождение с контрольными суммами | Статус качества; обнаруженные ограничения не скрываются |
| 5 | Grafio классифицирует операции и рассчитывает выручку, возвраты, выкупы, статьи расходов, их доли, себестоимость и выбранный вариант маржи | Согласованные показатели без подмены отсутствующих данных нулём |
| 6 | Grafio показывает текущую неделю рядом с историческими в столбчатой диаграмме с накоплением и таблице: маржа, себестоимость и расходы формируют структуру выкупов | Пользователь видит состав расходов, изменение относительно прошлых недель и состояние контрольного баланса |
| 7 | Пользователь выбирает изменившийся сегмент диаграммы или статью таблицы | Начинается исследование конкретного отклонения |
| 8 | Grafio раскрывает сумму до доступных товаров и операций, отдельно показывая начисления без связи с товаром | Пользователь понимает, из каких записей сложилась сумма и какие группы дали вклад |
| 9 | Пользователь проверяет возможное объяснение: например, сопоставляет операции с опубликованным тарифом и выполняет контрольный пересчёт | Гипотеза получает расчётное подтверждение либо требует дальнейшего исследования |
| 10 | Пользователь принимает рабочее решение: использовать результат, продолжить исследование, дождаться данных или передать проблему администратору | Понятное состояние анализа без автоматического заявления недоказанной причины |

## Результат выполнения

- Отчёт доступен в состоянии, соответствующем качеству данных.
- Пользователь видит суммы расходов и допустимые доли в выкупах.
- При полных данных и положительных выкупах пользователь видит контроль структуры: маржа + себестоимость + расходы = 100% выкупов.
- Пользователь может объяснить итог через доступные исходные операции.
- Версия расчёта и включение налогов и пользовательских расходов видны в отчёте.
- Система не объявляет временную связь доказанной причиной отклонения.

## Альтернативные потоки

| ID | Условие | Поведение Grafio | Возможное решение пользователя |
|---|---|---|---|
| A1 | Один из обязательных источников не получен или получен не полностью | Доступные показатели показываются с отметкой «Данные неполные». Показатели, зависящие от отсутствующих данных, получают состояние «Не рассчитывается» и называют недостающий источник | Использовать независимые показатели, дождаться обновления или проверить источник |
| A2 | Выкупы равны нулю | Суммы расходов остаются видимыми. Доли в выкупах не рассчитываются; причина: «Выкупы за неделю равны нулю» | Анализировать абсолютные суммы и возвраты |
| A3 | Выкупы отрицательны | Суммы расходов остаются видимыми. Доли в выкупах не рассчитываются; причина: «Возвраты за неделю превышают выручку» | Исследовать выручку и возвраты текущей недели |
| A4 | Расчётная и контрольная суммы различаются: Δ ≠ 0 | Новая версия не публикуется. Grafio показывает состояние «Требует проверки», сравниваемые суммы и точное расхождение; ненулевое значение не получает автоматическую причину | Перейти к операциям, найти пропуск, дубль или изменение методики; при необходимости обратиться к администратору |
| A5 | Найден неизвестный тип начисления, удержания или компенсации | Запись и её сумма видны отдельно как нераспределённые; Grafio не относит её к известной категории автоматически. Зависимые итоги помечаются как требующие проверки | Продолжить работу с известными данными и передать неизвестную операцию администратору |
| A6 | У статьи нет связи с товаром либо источник не предоставляет её | Операция остаётся в общей сумме и показывается в группе «Без привязки к товару» | Анализировать доступные реквизиты операции; не считать товарную детализацию полной |
| A7 | Администратор проверяет изменение методики площадки | Разделы остаются доступны с уведомлением о работе над расчётами. Затронутые показатели и периоды обозначены | Пользоваться незатронутыми данными и учитывать предупреждение |
| A8 | Опубликована новая версия правила с пересчётом истории | По умолчанию открыт исправленный отчёт; доступны исходная версия, перечень изменений, причина и затронутый период | Сравнить версии и при необходимости пересмотреть прежние выводы |
| A9 | Новое правило применяется только с текущего момента | Прошлые отчёты не изменяются; уведомление объясняет дату начала и отсутствие ретроспективного пересчёта | Учитывать различие методик при сравнении периодов |
| A10 | Налог или пользовательские расходы отключены | Категория исключена из расчёта, а состав маржи явно это показывает | Включить опцию при необходимости либо использовать результат без неё |
| A11 | Опция включена, но обязательных параметров или данных недостаточно | Категория и зависящий от неё итог не рассчитываются; отсутствующее значение не становится нулём | Заполнить настройку или отключить опцию с явным изменением состава результата |
| A12 | Пользовательский расход добавлен | Пользователь выбирает для этой записи учёт в неделю оплаты либо распределение по периоду; отчёт показывает применённый способ | Проверить выбранный период и влияние расхода на недельный результат |

## Решения, которые может поддержать отчёт

| Наблюдение | Решение пользователя |
|---|---|
| Структура расходов стабильна, сверки пройдены | Использовать отчёт при обсуждении результатов недели |
| Выросла сумма статьи | Проверить товары, операции и возможное изменение тарифа |
| Сумма стабильна, доля выросла | Проверить снижение выкупов, а не приписывать изменение самой статье |
| Данные неполные | Не использовать зависимые итоги до получения источника |
| Есть неизвестная операция или значимое расхождение | Передать проблему администратору и учитывать предупреждение |
| История пересчитана | Сравнить версии и определить, требуют ли прежние выводы пересмотра |

## Правила и ограничения сценария

1. Общие суммы групп и входящие в них статьи не суммируются повторно.
2. Отсутствующее значение отличается от нуля.
3. Прежняя ручная практика допускала небольшое расхождение. Для Grafio утверждено более строгое правило: сверка проходит только при Δ = 0 до пользовательского форматирования.
4. Контроль структуры рассчитывается в рублях независимо от диаграммы: выкупы − маржа − себестоимость − расходы.
5. Нормированная диаграмма на 100% не используется для контроля, поскольку она скрывает несоответствие суммы долей.
6. При отрицательной марже выход положительной части столбца выше 100% сам по себе не объявляется ошибкой.
7. Исторические недели должны явно показывать различие версий методики, если они рассчитаны неодинаково.
8. Новости и тарифы WB пользователь проверяет вне Grafio; автоматический сбор не входит в первую версию.
9. Grafio помогает исследовать возможную причину, но пользователь подтверждает вывод по данным.
10. Управление рекламными кампаниями, бюджетами и настройками WB не входит в сценарий.
