# Планы и прогнозы

Здесь закреплены правила планов и прогнозов. Основной пользовательский путь показан в прототипе.

## Зачем нужен модуль

Недельный отчёт отвечает на вопрос, что уже произошло. Модуль планов добавляет управленческий контекст:

- какой результат ожидался;
- насколько факт отклонился от цели;
- успевает ли кабинет выполнить план к концу периода;
- какой темп нужен в оставшиеся дни;
- можно ли доверять прогнозу при текущей полноте данных.

План не изменяет расчёт факта. Он хранится отдельно и сопоставляется с показателем той же методики, единицы, области и периода.

## Пользовательский сценарий

1. Пользователь выбирает юридическое лицо и один или несколько доступных кабинетов.
2. Выбирает неделю или календарный месяц.
3. Добавляет плановые показатели и единицы.
4. Для каждого показателя задаёт цель и тип сравнения.
5. Проверяет область и активирует версию плана.
6. В отчёте видит факт, цель, отклонение, выполнение и доступный прогноз.
7. При неполных данных видит причину ограничения вместо достоверного на вид результата.
8. При изменении плана создаёт новую версию; прежняя остаётся доступна для объяснения прошлых решений.

## Область плана

План создаётся для одной явно выбранной области:

- отдельный кабинет;
- несколько выбранных кабинетов одного юридического лица;
- всё юридическое лицо на момент активации плана.

Состав кабинетов фиксируется в версии плана. Подключение нового кабинета позднее не меняет активный план автоматически: пользователь создаёт новую версию или явно добавляет кабинет.

Планы пересекающихся уровней не суммируются. Например, план юридического лица и отдельный план кабинета показываются как разные управленческие контексты. Это защищает от двойного учёта.

Доступ к кабинету и его включение в тариф проверяются до создания плана. Один кабинет не ограничивает количество других кабинетов того же юридического лица.

## Плановые показатели

| Показатель | Доступные единицы | Тип по умолчанию | Как сравнивается |
|---|---|---|---|
| Заказы | ₽, шт. | Суммируемый | Факт не ниже цели |
| Выкупы | ₽, шт. | Суммируемый | Факт не ниже цели |
| Рекламные расходы | ₽ | Суммируемый бюджет | Факт не выше лимита |
| ДРР | % | Отношение | Факт не выше цели |
| Маржа | ₽ | Суммируемый | Факт не ниже цели |
| Маржинальность | % | Отношение | Факт не ниже цели |

Для заказов и выкупов пользователь выбирает рубли или штуки. Значения разных единиц не складываются и не сравниваются.

Для ДРР обязательно сохраняется вариант знаменателя: заказы, выкупы или рекламные заказы. План ДРР сравнивается только с фактом, рассчитанным на той же базе.

Тип сравнения хранится с показателем. Допустимы `не ниже`, `не выше` и `диапазон`; интерфейс предлагает безопасное значение по умолчанию из таблицы.

## Периоды

Поддерживаются два самостоятельных вида плана:

- **недельный** — ровно семь календарных дней, понедельник–воскресенье;
- **месячный** — календарный месяц.

Недельный план не является автоматически частью месячного. Если пользователь создал оба, система показывает их раздельно. Это исключает скрытую подмену одной управленческой цели другой.

Месячный план можно разложить по неделям для визуального контроля темпа. Такое разложение не создаёт самостоятельные недельные планы.

## Сплит недели между месяцами

Если факт доступен только за целую неделю, недельное значение относится к каждому месяцу пропорционально числу календарных дней:

```text
Дни пересечения =
MAX(0; MIN(конец недели; конец месяца)
       - MAX(начало недели; начало месяца) + 1)

Коэффициент сплита = дни пересечения / 7

Факт недели в месяце = факт недели × коэффициент сплита
```

Для недели `26.01.2026–01.02.2026` январю относятся `6/7` факта, февралю — `1/7`. Обе части сохраняются, а их сумма равна исходному недельному значению.

Если доступны полные дневные факты, используется их точная сумма. Сплит `1/7` является приближением и в этом случае не применяется.

Разложение месячного плана по календарным неделям считается иначе:

```text
Плановый фрагмент недели =
месячный план / число дней месяца × дни пересечения недели с месяцем
```

Это две разные операции: факт делится на семь дней своей недели, план — на число дней своего месяца.

## Выполнение суммируемого плана

Для рублей и штук:

```text
Накопленный факт = Σ фактов выбранного периода и области

Выполнение = накопленный факт / план

Отклонение = накопленный факт - план
```

Если цель типа `не выше`, как рекламный бюджет, интерфейс называет отношение **использованием лимита**, а не выполнением. Превышение 100% означает перерасход.

Для самостоятельного недельного плана:

```text
Выполнение недели = факт недели / план недели
```

Месячный коэффициент сплита в эту формулу не входит.

## Прогноз суммируемого показателя

Простой прогноз строится по среднему дневному темпу только для незавершённого периода с полными данными по завершённым дням:

```text
Средний дневной факт = накопленный факт / учтённые полные дни

Прогноз на конец периода =
средний дневной факт × календарные дни периода

Прогноз выполнения = прогноз на конец периода / план

Требуемый дневной темп =
(план - накопленный факт) / оставшиеся дни
```

В расчёт не включается текущий неполный день. Дата, до которой данные считаются полными, показывается рядом с прогнозом.

Если план уже достигнут, требуемый темп равен нулю. Если дней не осталось, прогноз заменяется итоговым фактом.

## Процентные цели

ДРР и маржинальность не суммируются, не умножаются на коэффициент сплита и не усредняются как готовые недельные проценты. Сначала агрегируются компоненты:

```text
ДРР периода =
Σ рекламных расходов / Σ выбранной базы ДРР

Маржинальность периода =
Σ маржи / Σ выкупов
```

Для процентной цели показываются:

- фактическое значение;
- цель;
- отклонение в процентных пунктах;
- состояние `в цели`, `лучше цели` или `хуже цели`.

Процент выполнения вида `факт / цель` не используется: для ДРР меньшее значение лучше, а отношение двух процентов плохо объясняет управленческий результат.

Прогноз процента рассчитывается из прогнозов числителя и знаменателя. Если компоненты прогнозируются одним и тем же линейным темпом, итоговый процент совпадёт с текущим; интерфейс не должен выдавать это за самостоятельную модель будущего поведения.

## Качество и доступность результата

| Состояние | Выполнение | Прогноз | Что видит пользователь |
|---|---:|---:|---|
| Все обязательные факты полны | Да | Да, для незавершённого периода | Значения и дата полноты |
| Один день ещё не завершён | По завершённым дням | Да | Текущий день исключён явно |
| Обязательный источник неполон | Нет для зависимого показателя | Нет | «Не рассчитывается» и причина |
| План отсутствует | Нет | Нет | Факт доступен, предлагается создать план |
| План равен нулю | Отклонение в ₽/шт. | Нет отношения к плану | Причина невозможности деления |
| Знаменатель процента равен нулю | Нет | Нет | Причина из паспорта метрики |
| План и факт используют разные единицы или базу ДРР | Нет | Нет | Требование выбрать сопоставимый факт |
| Методика факта изменилась | После выбора версии | После выбора версии | Граница версии и ссылка на сравнение |

Неполные данные не заменяются нулём. Цвет результата не назначается, пока система не может сопоставить факт и план.

## Версионность

Активированный план не перезаписывается. Изменение цели, состава кабинетов, периода, единицы, базы ДРР или типа сравнения создаёт новую версию.

Версия хранит:

- автора и время изменения;
- причину изменения;
- прежнее и новое значение;
- область и список кабинетов;
- набор показателей;
- версии методик факта, с которыми план сопоставлялся.

Для завершённого периода по умолчанию показывается версия плана, действовавшая в тот период. Пользователь может открыть более позднюю версию, но видит, что она не была исходной целью.

## Представление в интерфейсе

### Карточка плана

Для каждого показателя показываются:

1. факт и единица;
2. план и тип сравнения;
3. отклонение;
4. выполнение либо использование лимита;
5. прогноз и требуемый темп, если они допустимы;
6. состояние данных и дата их полноты.

### Недельный отчёт

Для завершённой недели показывается сравнение с самостоятельным недельным планом. Если есть только месячный план, рядом может отображаться плановый календарный фрагмент с явной подписью «часть месячного плана».

### Месячный экран

Показывает накопленный факт, цель, прогноз конца месяца, требуемый темп и вклад завершённых недель. Неделя на границе месяцев отображается двумя календарными фрагментами.

## Минимальная модель данных

| Сущность | Основные поля |
|---|---|
| `plan` | идентификатор, период, область, статус, номер версии, автор, причина изменения |
| `plan_scope` | тип области, юридическое лицо, зафиксированный список кабинетов |
| `plan_target` | код метрики, единица, целевое значение или границы, тип сравнения, база ДРР |
| `plan_version` | прежняя версия, время активации, автор, причина |
| `plan_fact_snapshot` | версия факта, дата полноты, значение, числитель и знаменатель для отношений |
| `plan_forecast` | метод, дата расчёта, учтённые дни, прогноз, требуемый темп, состояние качества |

Прогноз можно пересчитать, но его входы и метод сохраняются, чтобы результат был воспроизводим.

Наблюдаемое поведение плана закреплено требованиями [PFR-17—PFR-18](../requirements/functional-requirements.md) и [критериями приёмки](../requirements/acceptance-criteria.md#эпик-3-планы-и-недельная-аналитика). Формулы и исключения изложены выше.
