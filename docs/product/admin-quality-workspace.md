# Рабочее пространство администратора расчётов

Статус: проект административного интерфейса первой версии. Он определяет информационную архитектуру, действия, проверки и состояния; визуальный стиль и программная реализация не входят в документ.

## Коротко

**Зачем документ:** показать, как администратор разбирает расхождение или неизвестную операцию и безопасно меняет методику расчёта.

**Главное решение:** публикация правила возможна только после исследования, контрольного расчёта и выбора периода применения. Пользователь в это время видит последнюю опубликованную версию отчёта и уведомление о проверке.

**Пример:** WB добавил новое удержание. Grafio помещает его в очередь проблем, администратор изучает операции, создаёт правило, проверяет затронутые недели и публикует пересчёт вместе с объяснением изменений.

При первом чтении пройдите путь от «Очереди проблем» до «Уведомления». Перечни полей, прав и особых случаев можно читать при проверке интерфейса.

## Задача интерфейса

Рабочее пространство помогает администратору пройти проверяемый путь:

```text
сигнал → доказательства → решение о причине → проект правила
→ контрольный расчёт → способ применения → публикация → уведомление
```

Интерфейс не должен подсказывать неподтверждённую причину и не должен позволять опубликовать правило без контрольного расчёта. Пользователи продолжают видеть последнюю опубликованную версию отчёта с нейтральным предупреждением о проверке.

## Структура раздела

Административный раздел состоит из двух уровней:

1. **Очередь проблем** — поиск и приоритизация сигналов.
2. **Рабочее пространство проблемы** — исследование одного случая с сохранением общего контекста.

Это гибрид очереди и последовательного процесса. Шаги не являются жёстким мастером: администратор может возвращаться к доказательствам или проекту правила, но публикация доступна только после обязательных проверок.

## Очередь проблем

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ Проблемы расчёта     [Все WB ▼] [Состояние ▼] [Тип сигнала ▼] [Период ▼]   │
│                      [Только с влиянием на отчёты □]        [Поиск ______]   │
├──────────────────────────────────────────────────────────────────────────────┤
│ Новые 12   На разборе 4   На проверке 2   К публикации 1   Просрочены 3     │
├──────┬──────────────┬─────────────┬───────────┬──────────────┬───────────────┤
│ ID   │ Сигнал       │ Область     │ Влияние   │ Состояние    │ Ответственный │
│ Q-41 │ Новая операц.│ 3 кабинета  │ 128 400 ₽ │ Обнаружена   │ —             │
│ Q-40 │ Расхождение  │ WB-01, нед. │    842 ₽  │ На разборе   │ Администратор │
└──────┴──────────────┴─────────────┴───────────┴──────────────┴───────────────┘
```

### Поля строки

| Поле | Содержание |
|---|---|
| ID | Устойчивая ссылка на проблему |
| Сигнал | Неизвестная операция, изменение схемы, расхождение, неполная загрузка, изменение закрытого периода |
| Обнаружено | Дата и источник автоматического либо ручного сигнала |
| Область наблюдения | Площадка, кабинеты, отчёты и периоды, где найден сигнал |
| Финансовое влияние | Известная сумма либо «не определено»; отсутствие оценки не равно нулю |
| Затронутые показатели | Метрики, достоверность которых может измениться |
| Состояние | Текущее состояние жизненного цикла |
| Ответственный | Администратор, принявший проблему в работу |
| Возраст | Время с момента обнаружения и отметка установленного внутреннего срока |

### Фильтры и сортировка

- площадка, тип и состояние сигнала;
- кабинет, юридическое лицо и период;
- затронутая метрика или категория;
- наличие финансового влияния;
- ответственный и возраст проблемы;
- только новые значения схемы либо только изменённые закрытые отчёты.

Размер суммы помогает приоритизации, но не назначает причину и не закрывает проблему автоматически.

## Карточка проблемы

### Постоянная шапка

Верхняя часть остаётся видимой на всех шагах:

- ID и тип сигнала;
- состояние и ответственный;
- дата обнаружения и последнего изменения;
- наблюдаемая область;
- затронутые показатели и периоды;
- доступная оценка суммы;
- связанная проблема-дубликат либо родительская проблема;
- состояние пользовательского предупреждения.

Область наблюдения, область правила, область пересчёта и область уведомления показываются раздельно. Они могут различаться и не копируются одна в другую незаметно.

### Навигация по этапам

```text
[1 Сигнал] — [2 Доказательства] — [3 Решение] — [4 Правило]
        — [5 Проверка] — [6 Применение] — [7 Уведомление]
```

Каждый этап имеет состояние: `не начат`, `заполнен`, `требует внимания`, `пройден`. Сохранение черновика доступно на любом этапе. Публикация не зависит от визуального порядка вкладок, а зависит от контрольных условий.

## Этап 1. Сигнал

Интерфейс показывает факт, создавший проблему, без версии о причине.

| Тип | Что показывается |
|---|---|
| Неизвестная операция | новые значения `docTypeName`, `sellerOperName`, `bonusTypeName`, число строк и сумма доступных компонентов |
| Изменение схемы | добавленные, удалённые и изменившиеся ключи, первая и последняя загрузки с изменением |
| Расхождение | расчётная сумма, контрольная сумма, точная разница и валюта; успешное значение только 0 |
| Неполная загрузка | последняя полученная страница/курсор, ошибка, время попытки и зависимые показатели |
| Изменение закрытого периода | прежний и новый хеши, изменившиеся контрольные итоги и использовавшиеся версии отчёта |

Действия: `Принять в работу`, `Связать с существующей`, `Отметить дубликатом`. При переходе в «На разборе» администратор обязан подтвердить предварительную область. После этого Grafio публикует нейтральное пользовательское предупреждение по утверждённому шаблону.

## Этап 2. Доказательства

Администратор видит данные в порядке от общего к частному:

1. количество затронутых кабинетов, недель и операций;
2. суммы по значениям операции и денежным полям;
3. сравнение с предыдущей схемой или предыдущей загрузкой;
4. группировку по товарам при наличии связи;
5. обезличенные примеры исходных операций;
6. исходный документ и технические поля — по отдельному действию с аудитом просмотра.

Для каждой операции показываются загрузка, период, исходные значения, денежные компоненты, действовавшая версия правил и результат классификации. Несвязанные сигналы не объединяются одной причиной только из-за совпадения периода.

## Этап 3. Решение по результатам исследования

Администратор выбирает один результат и сохраняет обоснование:

| Решение | Когда применяется | Следующий шаг |
|---|---|---|
| Правило не нужно | Ошибка данных, подключения или настройки; методика корректна | Исправить источник/настройку и повторить проверку |
| Требуется изменение правила | Подтверждена новая или неверно учтённая операция | Создать проект правила |
| Собственная методика Grafio | Показатель воспроизводим только по доступным данным Grafio | Описать формулу и ограничение |
| Прекратить расчёт метрики | Достоверный расчёт невозможен | Определить зависимые показатели и дату прекращения |
| Дубликат | Причина уже исследуется в другой проблеме | Связать с основной проблемой |

До выбора решения поле «Подтверждённая причина» остаётся пустым. Рабочие заметки и гипотезы визуально отделены от подтверждённого вывода.

## Этап 4. Проект правила

### Конструктор условия

Правило составляется из разрешённых полей контракта:

```text
ЕСЛИ sellerOperName = «... »
 И bonusTypeName содержит «... »
 И docTypeName = «Продажа»
ТО источник суммы = penalty
   знак = +1
   эффект = расход
   категория = Штраф
```

| Блок | Обязательные данные |
|---|---|
| Условие | поле, оператор, значение, объединение И/ИЛИ |
| Эффект | денежное поле, знак, вид эффекта, категория или метрика |
| Приоритет | порядок относительно других правил той же области |
| Область | по умолчанию площадка и тип отчёта; дополнительные признаки подтверждаются данными; конкретный кабинет указывается только для обоснованного исключения |
| Период действия | дата начала и необязательная дата окончания |
| Основание | подтверждённая причина и ссылка на проблему |

Интерфейс сразу показывает количество операций, которое совпадёт с условием, и конфликты с действующими правилами. Это предварительная оценка, а не результат контрольной проверки.

Кабинет, в котором найден сигнал, не подставляется в область правила автоматически. При выборе «Только один кабинет» интерфейс требует указать кабинет, подтверждённую особенность, период действия и причину неприменимости общего правила. Такое исключение получает заметную отметку и отдельный контрольный расчёт.

## Этап 5. Контрольный расчёт

Проверка выполняется на выбранном обезличенном контрольном наборе и на затронутом диапазоне, если данные доступны.

### Сравнение до и после

| Область проверки | До | После | Разница | Результат |
|---|---:|---:|---:|---|
| Совпавшие операции | — | — | — | покрыты / не покрыты |
| Нераспределённые операции | — | — | — | уменьшились / появились новые |
| Неоднозначные правила | — | — | — | должно быть 0 |
| Контрольная сумма источника | — | — | — | расхождение должно быть равно 0 |
| Затронутые показатели | — | — | — | ожидаемое изменение |
| Незатронутые показатели | — | — | — | должны совпасть |
| Структура выкупов | — | — | — | контроль равен 0 ₽ |

Администратор может открыть любую разницу до операций. Ручная отметка «проверено» не заменяет автоматическую сверку.

### Блокирующие проверки

Публикация проекта правила недоступна, если выполняется хотя бы одно условие:

- есть неоднозначно классифицированные операции;
- остались необъяснённые операции, которые проект правила должен был покрыть;
- сопоставимое расхождение не равно 0;
- изменился показатель, заявленный как незатронутый;
- не проверены знак, возврат и сторно для применимых случаев;
- один денежный компонент учитывается повторно;
- не определены область и период действия;
- не указан результат для зависимых метрик.

Отсутствие тестового случая, например фактического сторно, показывается как «не проверено», а не как успешная проверка. Администратор либо добавляет контрольные данные, либо документирует ограничение и не публикует правило для неподтверждённой области.

## Этап 6. Способ применения

После успешного контрольного расчёта администратор выбирает одну ветвь.

### Пересчитать историю

Интерфейс показывает:

- первую и последнюю затронутые даты;
- кабинеты и версии отчётов;
- доступность исходных загрузок и настроек;
- прогнозируемое число новых версий отчёта;
- список показателей, которые изменятся.

Запуск создаёт задание пересчёта. Завершение задания ещё не означает публикацию: новые отчёты должны пройти повторную сверку. Прежние версии сохраняются.

### Применять только вперёд

Обязательны дата начала и причина отказа от пересчёта. Прошлые отчёты остаются без изменений и получают постоянную отметку о различии методик на границе сравнения.

### Ввести методику Grafio

Обязательны собственное название показателя, формула, источники, ограничения и дата начала. Интерфейс не позволяет представить её как расчёт WB.

### Прекратить расчёт

Обязательны дата прекращения, причина, перечень зависимых показателей и их новые состояния. Исторические значения остаются доступны с прежней версией методики.

## Этап 7. Уведомление

Уведомление строится из шаблона выбранной ветви. Администратор редактирует пояснение, но не может удалить обязательные данные.

| Событие | Обязательные данные |
|---|---|
| Идёт исследование | нейтральный статус, показатели, периоды, дата начала проверки |
| История пересчитана | подтверждённая причина, показатели, пересчитанный период, новая версия, ссылка на сравнение |
| Только вперёд | причина, дата начала и явное сообщение, что история не пересчитана |
| Методика Grafio | название, формула, источники и ограничения |
| Метрика остановлена | причина, дата и влияние на зависимые показатели |

Уведомление о завершении разрешено только после успешной проверки опубликованного результата. Круг получателей формируется по доступу к затронутым кабинетам и периодам; администратор видит число получателей до публикации.

## Поведение пользовательского отчёта

| Состояние проблемы | Что видит пользователь |
|---|---|
| Обнаружена, администратор ещё не подтвердил область | Никакого утверждения о проблеме; технический сигнал доступен только администратору |
| На разборе / проект / проверка | Последняя опубликованная версия и нейтральное предупреждение для подтверждённой области |
| Выполняется пересчёт | Последняя опубликованная версия, состояние работ и затронутые периоды |
| Пересчёт проверен и опубликован | Новая версия по умолчанию, прежняя версия и сравнение |
| Правило только вперёд | Неизменённая история и отметка границы методики |
| Метрика остановлена | История доступна; новые периоды имеют «Не рассчитывается» с причиной |

Проблема одной статьи не закрывает незатронутые разделы. Зависимые показатели могут временно иметь состояние «Не рассчитывается», если достоверное значение невозможно.

## Права и аудит

| Действие | Администратор Grafio | Менеджер/аналитик | Владелец/клиент |
|---|---:|---:|---:|
| Видеть очередь и технические доказательства | Да | Нет | Нет |
| Принять проблему и вести заметки | Да | Нет | Нет |
| Создать и проверить проект правила | Да | Нет | Нет |
| Опубликовать правило и выбрать ветвь | Да, при отдельном полномочии публикации | Нет | Нет |
| Видеть предупреждение, новую версию и сравнение | Да | В доступных кабинетах | В доступных кабинетах |
| Изменить пользовательские расходы или налог клиента | Только при отдельном клиентском полномочии | В пределах выданного доступа | Нет в базовой роли |

Журнал фиксирует принятие проблемы, изменение области, заметки, проект правила, контрольные запуски, решение о применении, публикацию, пересчёт и уведомление. Для каждого события сохраняются автор, время и прежнее/новое значение существенных полей.

## Системные состояния и действия

| Состояние | Разрешённые действия администратора | Условие перехода |
|---|---|---|
| Обнаружена | принять, связать, отметить дубликатом | подтверждена предварительная область либо связь с основной проблемой |
| На разборе | изучать, добавлять доказательства, фиксировать решение | сохранено обоснованное решение |
| Проект правила | редактировать условия и эффекты | проект отправлен на проверку |
| На проверке | запускать расчёт, открывать различия | все обязательные проверки пройдены |
| К публикации | выбрать способ применения, проверить уведомление | правило опубликовано и запущена выбранная ветвь |
| Пересчёт истории | наблюдать за заданиями и повторной сверкой | все новые версии проверены и опубликованы |
| Только вперёд | проверить активацию с даты | правило активно, уведомление опубликовано |
| Метрика остановлена | проверить зависимые показатели | новые состояния опубликованы и пользователи уведомлены |
| Закрыта | только просмотр и связь с новыми сигналами | повторное открытие создаёт новое событие истории |

## Обработка особых случаев

- Несколько сигналов могут быть связаны с одной основной проблемой только после подтверждения общей причины.
- Дубликат сохраняется для аудита и ссылается на основную проблему.
- Новое поле без финансового влияния всё равно регистрируется как изменение схемы, но не обязательно требует нового правила.
- Правило для одного кабинета допустимо только с явной областью и обоснованием; оно не становится общим правилом WB.
- Отсутствие примеров из других кабинетов не считается доказательством кабинетной специфики.
- Если исходные данные не позволяют проверить часть периода, интерфейс запрещает обозначить весь период как пересчитанный.
- При неоднозначном совпадении правил операции остаются непубликованными результатами проверки.
- Просмотр исходного ответа и чувствительных данных ограничивается ролью и попадает в аудит.
