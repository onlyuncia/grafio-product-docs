# Редакторское решение по комплекту документов

Цель этой подборки — показать связный кейс бизнес- и системного анализа без смешения текущего кода Grafio, целевого финансового контура и рабочих заметок по разработке макета. Исходная папка проекта сохранена без перемещения файлов.

## Что оставлено

- **Основной маршрут:** кейс, SRS, требования, BPMN, статусные модели, целевая ERD, OpenAPI, C4, sequence-диаграммы и ADR. Это материалы, по которым можно оценить решение без чтения всей папки.
- **Доказательная база:** AS-IS, исходные оценки, разбор книги WB, реестр метрик, маппинг полей и анализ текущего API. Они помогают отделить наблюдения от проектных решений.
- **Детализация сценариев:** Use Cases, User Stories, критерии приёмки, операционные процессы, планы и контроль расчётов.
- **Реестр требований первой версии** оставлен рядом с новой структурой требований: его идентификаторы используются в матрице прослеживаемости и других документах.

## Правила именования и размещения

Файлы названы по содержанию в `kebab-case` и разложены по функции: `context`, `research`, `requirements`, `processes`, `data`, `api`, `product`, `validation`, `architecture`. Сквозная нумерация исходных заметок удалена из имён и заголовков: порядок чтения задаёт [карта документов](README.md). Номера сохранены только там, где они обозначают порядок схем BPMN, sequence и ADR.

Русский язык остаётся языком содержания. Англоязычные имена файлов упрощают ссылки и перенос репозитория между системами. Ссылки в перенесённых Markdown-файлах пересчитаны относительно новых папок.

Снимки и кликабельный прототип представляют демонстрационный интерфейс. Документы целевого backend описывают проектное решение, а обзор существующего сервиса — исходный код другого репозитория; эти статусы нельзя смешивать.
