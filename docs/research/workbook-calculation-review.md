# Разбор расчётов в примере оцифровки WB

Статус: исследование существующего процесса по предоставленной книге. Найденная формула описывает поведение этой книги и не становится автоматически требованием Grafio.

Здесь собраны основные расчёты, результаты сверок и проблемы. Полный перечень показателей по всем листам, включая поля сводных и источники диаграмм, находится в [реестре показателей](metric-inventory.md).

Источник: предоставленная автором рабочая книга WB, название которой обезличено для публикации. Разбор проведён без изменения исходной книги. Адреса ниже относятся к этому файлу. В документ перенесены правила и ссылки на ячейки, без реестра операций, товарных идентификаторов и клиентских финансовых итогов.

## Способ проверки и границы выводов

Исследованы структура XLSX, формулы, сохранённые результаты, связи листов и определения сводных таблиц. В книге установлен ручной режим расчёта. Сохранённое значение не доказывает актуальность расчёта: полный пересчёт в Excel и обновление сводных таблиц не выполнялись. Внешние источники и актуальная схема API WB на этом шаге не проверялись.

Сначала полностью извлечены содержательные ячейки 18 небольших листов и первые 35 строк двух больших листов («База», «Детализация штрафов»). Затем полностью просмотрены сохранённые строки «Базы»: исходные категории, количество, ошибки, выбранные формулы и суммы для сверок. На «Детализации штрафов» содержимое после строки 35 не анализировалось. Размеры листов относятся к объявленным диапазонам, а не числу заполненных бизнес-записей.

### Результаты дополнительной проверки

- На «Базе» просмотрены 176 319 строк после заголовка. Исходные операции с номером отчёта заканчиваются на строке 170 989; далее 5 331 строка содержит протянутые формулы без исходных операций. В шести расчётных столбцах этих строк сохранены ошибки `#N/A`.
- В 28 447 строках с обоснованием «Продажа» или «Возврат» количество равно 1. Поэтому на этих данных нельзя отличить прямое суммирование цены от умножения на количество. Для подтверждения универсальной формулы нужен отдельный случай с количеством больше 1 либо подтверждённое описание смысла поля.
- Во всех найденных определениях формул F и G сохраняется прямое использование BN без умножения на BH. Проверены определения общих формул, используемых группами строк, и явные формулы; это проверка структуры формул, а не полный пересчёт Excel.
- В списке есть 30 уникальных номеров отчётов, в «Базе» — 29. Для отчёта из строки 17 списка не найдена детализация. Ненулевые расхождения Y17:AB17 воспроизводятся независимым суммированием. Причина отсутствия детализации не установлена.
- Для остальных 29 строк списка восемь проверенных контрольных сумм совпали с суммами сохранённых значений «Базы» в пределах 0,01 ₽. Для строки 17 не совпали выплата, продажи, перечисление и логистика. Доплаты AD не включены в эти восемь проверок из-за сломанной ссылки.
- Для недели в столбце N «Метрик» независимо агрегированы продажи, возвраты, выкупы, комиссия и себестоимость, проверена доля комиссии. Расхождения с сохранёнными итогами не превышают 0,01 ₽ для денежных сумм; доля совпала с точностью вычислений.

Порог 0,01 ₽ использован только для диагностики этого файла и не утверждён как требование Grafio. Независимая агрегация сохранённых значений проверяет их согласованность, но не доказывает правильность всех первичных формул, свежесть данных или актуальность методики площадки.

## Продажи, возвраты и выкупы

Автор подтвердил устно вариант «количество × цена». В предоставленной книге обнаружена другая формула суммы. Это расхождение источников зафиксировано явно, без выбора одной версии по умолчанию.

| Элемент | Правило в книге | Подтверждение |
|---|---|---|
| Общий знак документа | «Продажа» → +1; «Возврат» → −1; другое → 0 | «База» A2, исходное поле BD1 «Тип документа» |
| Классификация продаж | Положительные операции: «Продажа», «Сторно возвратов», «Корректная продажа», «коррекция продаж». Отрицательные: «Возврат», «Сторно продаж», «Корректный возврат». Прочие → 0 | «База» C2, поле BE1 «Обоснование для оплаты» |
| Продано, шт. | При положительном коэффициенте берётся BH «Кол-во»; для «коррекция продаж» устанавливается 0 | «База» D2 |
| Возвращено, шт. | При отрицательном коэффициенте берётся BH; для «коррекция продаж» устанавливается 0 | «База» E2 |
| Продано, ₽ | `IF(D2>0,BN2,0)` — взять BN при положительном количестве продаж | «База» F2; BN1 «Цена розничная с учетом согласованной скидки» |
| Возвращено, ₽ | `IF(E2>0,ABS(BN2),0)` — взять модуль BN при положительном количестве возвратов | «База» G2 |
| Выкупы, шт. | Продано минус возвращено | «База» H2; «Метрики» N20 |
| Выкупы, ₽ | Сумма продаж минус сумма возвратов | «База» I2; «Метрики» N21 |
| Недельные суммы | Суммирование D/F/E/G по номеру недели AI | «Метрики» N12:N17 |

Важное различие терминов: **«Выручка руб.» на «Базе» (I) уже равна продажам за вычетом возвратов**, тогда как «Выручка (₽)» на «Метриках» (строка 13) суммирует продажи до возвратов. «Выкупы (₽)» на «Метриках» (строка 21) соответствует чистой сумме I. В словаре Grafio этим величинам нужны разные однозначные определения.

Для сторно и корректировок одного фильтра по типу документа недостаточно, чтобы воспроизвести найденную логику. Необходимость каждого исключения и правильность исключения «коррекция продаж» ещё требуется подтвердить по смыслу исходных операций.

## Расходы и финансовый результат

Формулы ниже описаны по строке 2 «Базы» и столбцу N «Метрик». Знаки сохранены как в книге; экономическая трактовка спорных случаев ещё не согласована.

| Показатель / правило | Расчёт и источник | Где проверено |
|---|---|---|
| К перечислению за товар | Исходная сумма CB × знак документа A, минус компенсации Q и R | «База» J2 |
| Комиссия | Чистая сумма I − J − эквайринг L + корректировка эквайринга M | «База» K2; «Метрики» N50 |
| Эквайринг | BW учитывается при положительном проценте BX, со знаком A; в L добавляется M. Недельная метрика отдельно вычитает M | «База» L2:M2; «Метрики» N64 |
| СПП, ₽ | Чистая сумма I − «WB реализовал» Y. Y = A × ABS(BJ) | «База» N2, Y2 |
| Прямая логистика | Использует количество доставок CC, возвратов CD, сумму CE и знак сторно B. Есть отдельная ветка для отрицательной суммы сторно | «База» B2, U2 |
| Обратная логистика | При CD > 0 берётся CE × B | «База» V2 |
| Доставка всего | Прямая + обратная логистика | «Метрики» N54, N56, N58 |
| Компенсации | Категории из BE сопоставляются со списками допустимых названий, сумма берётся из CB со знаком A | «База» Q2:R2 |
| Брак и ущерб, количество | Брак учитывается с проверкой первого появления составного ключа; ущерб — по BH со знаком компенсации | «База» O2:P2, S2:T2 |
| Хранение | Если сумма отдельного листа хранения равна 0, используется DB. Иначе выполняется распределение по неделе, году и артикулу; часть без сопоставленного артикула распределяется отдельно | «База» AC2; «Хранение» Y2:AC2 |
| Приёмка | Недельная сумма исходного DD. В расчёте выплаты X использован ABS(DD) | «Метрики» N96; «База» X2 |
| Рекламные расходы | Сумма CPC и CPM. В N69 и N71 нет формул получения из «Базы» | «Метрики» N67, N69, N71 |
| Дополнительные услуги | Поиск названий «WB…Продвижение», «ВБ.Медиа», «Джем» в CK. Суммы берутся из X с изменением знака | «Метрики» N89:N91 |
| Прочие удержания | Сумма DC минус выделенные рекламные / маркетинговые услуги | «Метрики» N112 |
| Общие затраты недельного отчёта | Сумма девяти групп, в том числе рекламы CPC/CPM. Себестоимость сюда не включена | «Метрики» N120 |
| Доля расходов | Сумма статьи / выкупы в рублях | Например, «Метрики» N51, N55, N68, N95, N121 |
| Расчётное «К перечислению» | Выкупы − общие затраты | «Метрики» N123 |
| Себестоимость | Поиск по поставке + коду номенклатуры, затем резервный поиск по номенклатуре. Используются коэффициент операции C и количества брака/ущерба S/T, а не прямое умножение на BH | «База» AB2; «Себестоимость» A3, G3; «Метрики» N126 |
| «Маржинальность (₽)» | Расчётное «К перечислению» − себестоимость | «Метрики» N129 |
| Маржинальность, % | Полученный денежный результат / выкупы в рублях | «Метрики» N130 |
| Прибыль на единицу | Денежный результат / выкупы в штуках | «Метрики» N132 |
| Внешние расходы | Общие и поартикульные расходы распределяются пропорционально I в рамках месяца и года; строки, помеченные самовыкупами, исключаются | «База» AF2; «Внешние расходы» K2:N2 |
| Самовыкупы | Поиск в отдельном листе по CY (Srid), учёт суммы и признака | «База» AD2:AE2; «Самовыкупы» A1:D1 |

«К перечислению» на листе «Метрики» — расчётный результат, включающий выбранный состав затрат. Он не тождественен автоматически ни исходному CB, ни рассчитанной «Оплате на РС» X, ни фактическому движению денег в банке.

В сводном P&L присутствует иная формула: **ЧП = Оплата на РС − Себестоимость − Налог − Всего внешних расходов**. Она подтверждена определением вычисляемого поля сводной таблицы и описанием «Инфо» C22; результат представлен в «P&L» A30:A35. Недельную «Маржинальность (₽)» и эту ЧП нельзя объединять без согласования состава расходов. Налоговые настройки исследованы только как логика файла, а не как проверка применимого налогового законодательства.

## Периоды и контрольные суммы

- «База» AG2 получает начало периода по номеру отчёта AT из «Списка отчётов» W. AI2 выводит номер недели через WEEKNUM с параметром 2. AJ2 аналогично выводит неделю заказа из BF.
- Недельные SUMIFS в «Метриках», например N13, фильтруют только номер недели. Год, кабинет и юридическое лицо в этих формулах явно не заданы. Для Grafio область расчёта потребуется определять независимо от того, какие данные сейчас собраны в одной книге.
- Месячные формулы, например «Метрики (Месяц)» D6, фильтруют название месяца AK без года.
- Сверки «Список отчётов» Y:AG выполняются по номеру отчёта, а не по одной только неделе: выплата, продажи, к перечислению, логистика, штрафы, доплаты, хранение, приёмка, прочие удержания.
- Для сверки продажи используется «WB реализовал» Y, а не сумма продаж F. Для сверки перечисления — J + Q + R. Это разные контрольные величины.
- В сохранённых проверках встречаются остатки порядка 10⁻⁹–10⁻⁸. Требование «должно быть 0» нужно формализовать через правила точности и допустимого расхождения, а не автоматически считать любой ненулевой остаток новой статьёй.

## Найденные проблемы и вопросы к методике

| Наблюдение | Основание | Следствие для анализа |
|---|---|---|
| В проверке доплат сломана ссылка | «Список отчётов» AD2:AD31 содержит `#REF!` | Этот контроль в предоставленном виде не подтверждает корректность доплат |
| В накопительных значениях и динамике первой расчётной недели есть сломанные ссылки | «Метрики» N22, N23, N31, N32 | IFERROR в части формул скрывает ошибку пустым результатом |
| Для утилизации вместо номера недели используется сумма органических заказов | «Метрики» N102 сравнивает AI с N37 | Ошибка выбора критерия; аналогичная проблема в месячной формуле D45 |
| Для дополнительной части штрафов вместо номера недели используется динамика выкупов | «Метрики» N109 сравнивает AI с N23 | Ошибка выбора критерия; месячный аналог D42 |
| «Конец недели» ссылается на начало | «База» AH2: VLOOKUP по A:X с индексом 23 возвращает W; конец хранится в X | Может влиять на определение месяца/года при отсутствии даты продажи |
| Подозрительная ссылка на ставку налога | «База» AA2 ссылается на «Справка2» E401615, тогда как подпись и ставка находятся в D8:E8 | Проверить перенос формулы. В выбранной настройке E6 = 3 налог отключён, поэтому текущий нулевой результат не проверяет рабочую налоговую ветку |
| Знаки компенсаций и приёмки требуют согласования | «Метрики» N107 и N108 используют разные знаки; N96 берёт DD напрямую, а X использует ABS(DD) | Нельзя унифицировать статьи только по названиям; нужны примеры начисления и отмены |
| Приёмка в вычисляемом поле сводной содержит ошибку | Определение поля «Приемка» содержит `ABS(#NAME?)`; «Инфо» C13 описывает ссылку на «Платная приемка», текущий заголовок DD — «Операции на приемке» | Зафиксировано расхождение определения и структуры; корректность показателей сводной требует отдельной проверки |
| Есть сохранённые ошибки в дополнительных листах | «Хранение» AB2:AB5 — `#N/A`; «Самовыкупы» B2/D2 — `#NAME?` | Часть листов может быть незаполненным шаблоном. Ошибки не следует без проверки считать активными расходами клиента |
| ДРР при любой ошибке превращается в 0 | «Метрики» N82:N84 | Для Grafio потребуется различать нулевые расходы, отсутствие данных и невозможность расчёта |
| Источники периодов и режим ручного расчёта требуют контроля актуальности | Недельные и месячные формулы, настройки книги | Сохранённые значения и наличие формул не доказывают синхронность всех представлений |
| В списке есть отчёт без детализации | «Список отчётов» строка 17; полный просмотр AT на «Базе» | Нужен контроль полноты загрузки по ожидаемым отчётам. Такое расхождение не доказывает появления новой статьи |
| Формулы продолжаются после конца исходных операций | «База» строки 170990:176320; ошибки в AG, AH, AI, AK, AL, AS | Отличать отсутствие исходной строки от неизвестной операции и ошибки в существующей операции |

Проблемы зафиксированы для извлечения требований к Grafio. Книга не исправлялась. Масштаб влияния каждой проблемы на клиентские решения не оценён.

## Что переносим в аналитическое портфолио

1. Словарь показателей с единицами, формулами, периодом и смыслом знаков.
2. Сопоставление источников: поле → правило обработки → показатель → контрольная сумма.
3. Правила обработки продаж, возвратов, сторно, компенсаций и неизвестных операций.
4. Примеры проверок: повторный учёт возврата, неверный период, отсутствующая себестоимость, ошибочная ссылка и нулевая база доли.
5. Разделение рассчитанных показателей и внешних исходных данных для рекламы, заказов, конверсий и планов.

Это направления дальнейшей работы, а не утверждённый объём первой версии. Оригинальный клиентский файл не добавлен в репозиторий. Для публичных примеров можно использовать отдельно подготовленные учебные данные.
