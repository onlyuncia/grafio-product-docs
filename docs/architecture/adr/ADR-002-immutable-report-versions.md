# ADR-002. Неизменяемые версии отчётов и методики

| Атрибут | Значение |
|---|---|
| Статус | Принято |
| Решение | Публикация методики или пересчёт создают новые версии; опубликованная история не перезаписывается. |

## Контекст

Правила классификации операций WB могут меняться, а поздние данные и исправления требуют пересчёта. Пользователь должен понимать, какая методика и какие входные данные сформировали конкретную неделю.

## Альтернативы

1. Пересчитывать прошлый отчёт на месте — простой интерфейс, но потеря воспроизводимости и невозможность объяснить изменение.
2. Хранить только журнал изменений — частично сохраняет историю, но требует повторного расчёта для любого сравнения.
3. Создавать неизменяемые версии отчётов и методики — сохраняет источник результата и позволяет сравнивать версии.

## Решение

Выбрана третья альтернатива. Версия отчёта содержит время расчёта, версию методики, качество и показатели. При пересчёте истории создаются новые версии затронутых недель; при применении вперёд прежние недели остаются неизменными.

## Последствия

- API читает последнюю опубликованную версию по умолчанию, но позволяет открыть историю и сравнение.
- Необходимы статусы версий и правила видимости для клиента.
- Объём исторических данных растёт, поэтому нужны индексы, сроки хранения и контроль стоимости.
