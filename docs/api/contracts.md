# Контракты целевого API Grafio

Этот документ поясняет целевой API-контракт Grafio. Актуальная машиночитаемая версия — [OpenAPI 3.1 JSON](openapi.json); [публичная предыдущая версия в SwaggerHub](https://app.swaggerhub.com/apis/grafio/api-grafio/3.0.0-target) будет обновлена позже. Описанные операции не следует считать уже реализованными.

## Общие соглашения

| Область | Контракт |
|---|---|
| Базовый путь | `/v1` в целевом OpenAPI; размещение за существующим шлюзом `/api` относится к развёртыванию и не меняет путь контракта. |
| Аутентификация | `Authorization: Bearer <JWT>`; refresh token не является параметром бизнесовых endpoint’ов. |
| Изоляция | Backend выводит организацию и полномочия из токена, затем проверяет область юридического лица, кабинета и действия. Нельзя передать чужой `organizationId` как способ расширить доступ. |
| Ошибки | `application/problem+json`: `code`, безопасный `title`, необязательный `detail`, `correlationId`. |
| Асинхронные действия | Возвращают `202` с `jobId`, `correlationId`, `status: accepted`; статус читается из объекта или задания. |
| Идемпотентность | Команды загрузки, верификации, публикации и закрытия используют `command_id`/идемпотентный ключ на сервере. Повтор не создаёт дубль объекта или расчёта. |
| Версии | Чтение отчёта без `reportVersionId` возвращает последнюю опубликованную версию; черновик не выдаётся как актуальный. `publicationStatus` и `qualityLevel` передаются раздельно. |

## Группы endpoint’ов

| Группа | Цель | Ключевые операции |
|---|---|---|
| Отчёты | Получить опубликованный финансовый результат и детализацию | контекст выбора, недельный отчёт, история и сравнение версий, качество данных, детализация метрики |
| Финансовые настройки | Учесть дополнительный расход и налоговое правило юрлица | список и создание пользовательских расходов, список опубликованных налоговых правил, чтение и изменение настройки юрлица |
| Недельная аналитика | Отдать тематические графики в согласованной семантике | темы, серии, точки, тип визуализации, «Что изменилось» |
| Контроль расчётов | Передать проблему, вести контекст и получить результат | создать, комментировать, доказательства, задачи, статусы, повторная отправка |
| Методика Grafio | Внутреннее расследование и выпуск методики | очередь, карточка, назначение, черновик правила, контроль, публикация |
| Планы | Управлять версиями плана и читать факт–план | список, создание, чтение, изменение, активация, архивирование, факт–план |
| Мой дашборд | Управлять личными листами и виджетами | листы, поддержанные KPI/графики, перемещение, размер, настройка, удаление |
| Команда | Управлять членством и областями доступа | участники, приглашения, принятие, роль/область, отзыв |
| Безопасность | Управлять персональной защитой доступа | настройки, 2FA, активные сессии, API-ключи |
| Кабинеты маркетплейсов | Управлять кабинетами WB | список, создание, верификация, изменение, отключение, история и повтор загрузки |
| Организация | Создать организацию и юридические лица | чтение/создание организации, список/создание юрлиц |
| Фоновые операции и аудит | Сделать асинхронность и существенные действия наблюдаемыми | статус `jobId`, журнал аудита |
| Жизненный цикл организации | Закрыть организацию контролируемо | запрос, статус, отмена до точки невозврата, экспорт |

## Покрытие функциональных требований

Контракт описывает целевые серверные операции PFR-01—PFR-29 из [функциональных требований](../requirements/functional-requirements.md). PFR-30—PFR-34 описывают РНП, Товары и Студию; их интерфейсы не входят в этот целевой финансовый OpenAPI. Поведение canvas (сетка, миникарта, линейки, режим редактирования и позиционирование панелей) остаётся клиентской ответственностью и не требует самостоятельных endpoint’ов.

| Контур | API-покрытие |
|---|---|
| Отчёт и качество данных, PFR-01—PFR-10 | Контекст выбора, недельный отчёт, история/сравнение версий, качество, детализация и методика |
| Кейсы и методика, PFR-11—PFR-16 | Кейсы, комментарии, доказательства, задачи, клиентские статусы; расследования, черновики, проверка и публикация правил |
| Планы, аналитика и дашборд, PFR-17—PFR-23 | Полный жизненный цикл планов, тематическая аналитика, CRUD листов и виджетов |
| Команда и безопасность, PFR-24—PFR-27 | Участники и приглашения, роли и области, 2FA, сессии, ключи, журнал аудита |
| Финансовые настройки, PFR-28—PFR-29 | Пользовательский расход со способом распределения; выбор опубликованного налогового правила юрлица |

## Контракты, требующие особого внимания

### Отчёт

`GET /reports/weekly` принимает только область отчёта и период. В ответе обязательны контекст, версия с отдельными `publicationStatus` и `qualityLevel`, независимые состояния качества и массив метрик. Метрика имеет либо значение, либо состояние `not_calculated` с причиной; API не подменяет отсутствие нулём. При обязательной сверке `Δ ≠ 0` новая версия не становится опубликованной.

`GET /reports/weekly/{reportVersionId}/metrics/{metricCode}/details` возвращает только доступную детализацию. Пагинация обязательна для больших наборов операций.

### Методика и пересчёт

`POST /admin/investigations/{investigationId}/publish` принимает результат проверки, область, дату и способ применения. Команда возвращает `202`, поскольку публикация и пересчёт — фоновые операции. Правила блокировки публикации определены в [Бизнес-правила Grafio](../requirements/business-rules.md) и [Статусные модели Grafio](../processes/status-models.md).

### Секреты и доступ

`POST /marketplace-accounts` принимает WB-токен только в request body с `writeOnly: true`. Он сохраняется в защищённом хранилище, а последующие ответы возвращают только статус подключения. Endpoint’ы команды проверяют полномочие владельца и создают аудит изменения.

### Закрытие организации

`POST /organization/closure` не удаляет данные синхронно. Он принимает подтверждённый запрос, возвращает `jobId`, останавливает новые интеграции и запускает процесс хранения/удаления из [BPMN-07](../processes/bpmn/07-client-offboarding-and-deletion.bpmn).

## Решения, которые фиксируются при реализации

1. Сохранять `/v1` как базовый путь целевого контракта; изменение внешнего префикса требует отдельного решения о маршрутизации и версии API.
2. Для больших детализаций допускается заменить `page` на cursor-пагинацию без изменения предметной модели.
3. Доказательства кейса хранятся вне основной БД; API выдаёт только короткоживущую безопасную ссылку `downloadUrl`.
4. Все длительные операции возвращают `jobId`; единый `GET /jobs/{jobId}` показывает их состояние и безопасный результат.
5. Схемы Fastify/Zod генерируются из OpenAPI либо проверяются контрактными тестами, чтобы код и спецификация не расходились.
